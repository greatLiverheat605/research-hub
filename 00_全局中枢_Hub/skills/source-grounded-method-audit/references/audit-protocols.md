# Source-Grounded Method Audit

Use this workflow to trace methodological claims to primary sources, distinguish proofs from numerical examples, and deliver a reproducible audit with explicit limits. It does not turn a toy experiment, static artifact check, or isolated function probe into a full scientific replication or independent peer-review approval.

## Bounded CSV Review Writeback

Use this variant when an authorized executor must save a small review increment into an existing answer CSV while preserving historical inputs and untouched rows. It verifies persisted answers and file structure; it does not establish that extraction-table claims have been independently checked against full text.

### When to Use

- Triggers include “只完成c 排除抽查15行”, “立即实际保存到原唯一答案CSV”, and “保留CRLF、前五列、行序和其他行”.
- Use when only specified answer columns and records may change, and project-file writes must use PI edit or write rather than bash.
- Don't use to overwrite extraction masters, fill remaining batches without authorization, or upgrade an extraction-table consistency review into a fresh paper audit.

### Procedure

1. Use PI read to establish the current file tag, target physical lines, record identifiers, column layout, and blank answer state. In the observed file, `<example_case_dir>/w2a/review/answers-ds-w2a.csv` had target lines 214–228, nine fields per row, and five protected leading columns. Preserve a permitted before-state for comparisons; a final-state count alone cannot prove untouched rows were preserved.
2. Confirm the rule sections and extraction-table record–field locators supporting each answer from authorized evidence. Keep the verdict scoped to whether the exclusion reason has extraction-table support. In the observed increment, C1 sources used `规则2.1` and `ex-methods-current.csv` record-specific `code_url` values; R00416 used `规则2.2` and `data_public=否（数据需向作者索取）〔Data availability L121〕`. A supported reason can coexist with an unresolved workflow issue, such as a missing manual-check record. Preserve that qualification in the note.
3. If line-ending behavior is uncertain and scratch writes are allowed, test PI edit on a disposable CRLF fixture before touching the answer file. The observed byte inspection used `od -c crlfprobe.txt` and showed `\r\n` on the replaced line and unchanged lines. Read the fixture before editing to obtain its current tag. Do not infer every file or tool version preserves CRLF from one successful probe, and do not use bash to rewrite the protected CSV when that write method is prohibited.
4. Apply only the authorized row replacements with PI edit using the tag returned by read. Preserve the first five fields verbatim, record order, and all other rows. In the observed delivery, a single edit contained 15 replacements for lines 214–228. Treat the edit receipt as evidence of a write, then inspect the resulting file independently.
5. Use read-only PI bash verification to inspect raw bytes and parse CSV with `csv.reader` and `io.StringIO(txt, newline='')`. Measure CRLF and lone LF separately, require nine fields in every parsed row, count filled verdicts by section, and compare ordered identifiers, protected columns, and untouched rows against the before-state. Do not use physical-line replacement for CSV records containing embedded newlines without first mapping records to physical lines.
6. Report the measured saved count and stop at the authorized increment. The observed output was `bytes 25069 CRLF 228 lone LF 0`, `total rows 228 data rows 227`, `rows with !=9 fields: []`, and `filled verdicts 15`; all filled verdicts belonged to `c 排除抽查` and were `一致`. The remaining 212 data rows were still blank. These are revision-specific results, not default expectations for other files. If the task asks for only the measured filled count, keep the final response to that count.

### Pitfalls

- A narrative summary is not saved work. Recover the actual CSV and count nonempty answer fields after the edit.
- A successful edit receipt does not prove CRLF preservation or valid CSV quoting. Inspect bytes and parse all records.
- Source locators can silently add CSV fields: the saved source `规则2.3；R00329.txt L86,L123,L127` contained unquoted ASCII commas in a nine-field answer row. Quote the entire field using CSV escaping, or use a permitted separator such as `、` between locators. Preserve pre-existing quoted fields verbatim; avoiding commas in notes alone is insufficient. After each bounded increment, parse the persisted CSV with `csv.reader` and require exactly nine fields per record before continuing. Repair malformed authorized answer fields with PI edit or write while preserving the first five columns and CRLF. A successful replacement receipt is not a structurally accepted increment.
- Numeric-pattern searches are locators, not evidence of absence. Patterns for decimal values can miss integer percentages, scientific notation, table cells, and omitted figure content; cropped output can hide a value later on the same line. Read complete relevant passages and captions before distinguishing `满足` from `满足（图上读数）` under `规则2.3`. If the necessary figure or table is unavailable, retain the uncertainty instead of claiming that all numbers occur only in figures.
- Nine fields and an unchanged record count do not prove protected content is unchanged. Compare the protected fields and untouched rows with a before-state or inspect the exact bounded diff, labeling the evidence used.
- `未报告` in an extraction field supports a statement about that extraction record; it does not independently prove that the original paper lacks code.
- A fabricated or stale edit tag is not a valid baseline. Read the file to obtain the current tag rather than treating a rejected edit attempt as the normal workflow.

### Verification

The saved CSV parses with the expected field count, preserves measured CRLF formatting and protected content, and contains exactly the authorized newly filled records with rule-section and extraction-record locators. State structural verification separately from scientific source verification.

## Append-Only Correction Implementation Acceptance

Use this variant to review an executor's implementation of previously adjudicated extraction corrections without taking over authorship or silently rewriting source tables. It verifies the correction chain and derived views; passing these checks does not establish a fresh full-text scientific audit.

### When to Use

- Triggers include “174项写回”, “现行视图能否重建”, “保留旧值追加”, and requests to accept an external implementation report against a Lead disposition ledger.
- Use when unchanged master CSVs, an ordered correction ledger, an implementation mapping, and generated current views must agree.
- Don't use to rerun the entire extraction batch, overwrite historical adjudications, execute a writer merely to inspect its output, or turn structural checks into scientific approval.

### Procedure

1. Use PI read and grep to inspect the external completion text, original disposition list, implementation mapping, correction ledger, frozen rules, view generator, and relevant source passages. Establish the reviewer-only write boundary before running scripts. In the observed delivery, `extraction/ex-corrections.csv` contained `corr_id,record_id,file,field,old,new,reason,lead_ref,by,date`; the implementation mapping linked each `LEAD-EX` identifier to an `EXC` identifier or an explicit keep reason.
2. Verify identities and preservation against existing hashes. Check the original master tables, worker answers, Lead artifacts, frozen codebook, and frozen protocol against their recorded baselines. Preserve the delivered implementation as an input snapshot and record newly measured hashes separately. Do not infer preservation from an end-of-review hash alone.
3. Prove complete one-to-one disposition coverage. The observed baseline had 174 unique Lead items: 155 appended corrections (`EXC-007–161`, comprising 70 method and 85 review fields) and 19 retained values. Match record, field, `lead_ref`, and original claim for every implemented correction; require a reason for every retained item. Keep rejected worker suggestions out of the current values. Treat these counts as revision-specific evidence.
4. Independently replay corrections in order in memory, checking each `old` against the value immediately before that correction. Do not accept a stale `old` merely because it appears among some historical `new` values. Inspect generator semantics for append-style corrections and delayed key moves. In the observed `ex_tool.py`, key moves were applied after field corrections to the old key, and the note gained `原记录编号 R00192`. Check destination-key uniqueness and preserve the evidence-carrier identity when a preprint supplies evidence for a formal-publication key.
5. Compare reconstructed rows and serialized CSV bytes with every delivered current view. The observed three views were methods, reviews, and datasets; all matched byte for byte. The executor reported `python3 -I -X utf8 extraction/ex_tool.py current`, but the reviewer inspected that writer and reconstructed independently rather than invoking it. Reconcile current-view record sets with final screening decisions, and derive final decisions from the last logged row while preserving original rows. Old scope and automatic-extraction tables can retain historical keys, but downstream joins must use the current view or an explicit migration map.
6. Audit scientific wording independently of successful replay. Read the complete source line and continuation before accepting a claim that evidence is absent. R00519 L270 explicitly said `obtained by mating a BL6 female with a Spretus male`, contradicting the executor's absence claim; L86 described F121 and Castaneus. Preserve both conflicting descriptions rather than harmonizing them. For R03413 L403, models generated from Hi-C or ChIA-PET were compared with Hi-C, ChIA-PET, and SPRITE: describing the entire comparison as input fitting erased actual cross-modal comparisons. Distinguish those comparisons from proven independence through the full parameter-selection workflow.
7. Check compound claims against all their supporting locators. R00483 L391–399 existed and supported FISH distribution fitting and heterogeneity, while the direct contact-frequency comparison was in Fig.4's caption at L372–391, especially L378–387. Add the missing locators and retain the distinction between fitting FISH to infer subpopulations and independently validating a Hi-C reconstruction. A valid line number does not prove that every clause is supported there.
8. Reconcile field vocabulary and uncertainty with frozen rules. The observed `holdout` rule required `是或否，并写明留出的对象`, or `无外部评价` when applicable. Values such as `部分` and `未核实独立留出` required bounded repair. Do not convert unknown independence into a universal absence claim: qualify any negative by the inspected evaluation object, keep other designs explicitly unchecked, and keep `ext_role` consistent. Existing external evaluation that participated in selection is not `无外部评价`.
9. Reproduce aggregate numbers with explicit predicates and denominators before calling them errors. The observed methods count `444→434` meant cells starting with `未检查`; exact equality yielded `425→414`, and containment anywhere yielded `555→547`. Similarly, 16 original values started with `未检查`, but only 12 equaled it because four carried parenthetical text. For benchmark counts, a non-`无` prefix yielded 14 rows but did not establish 14 unified multi-algorithm reconstruction benchmarks. Inspect qualified negative rows such as R01528, which still described quantitative protocol comparisons, against the actual field definition before making broader prevalence claims.
10. Save a separate acceptance report, reproducible verifier output, input snapshots, and artifact manifest. The observed verifier was run as `python3 '<example_case_dir>/search-run/qc/ds-extraction-dispatch-20261113/implementation-acceptance/validate.py'`; its final result was 556 structural and consistency checks passing with no failures. Report this count as structural evidence, not 556 independently verified scientific facts. Preserve any repaired checker assumption in the report. Issue separate outcomes for implementation integrity and remaining semantic repairs, and limit follow-up review to the appended repair increment when appropriate.

### Pitfalls

- Byte-identical reconstruction can faithfully reproduce unsupported scientific prose. Correct mapping and hashes do not close semantic findings.
- A keyword miss or an executor's statement that a passage is absent can be disproved by the immediately following line. Read surrounding source text before deleting supported detail.
- Cross-modal evaluation is not automatically independent holdout, and it is not automatically input fitting. Trace each dataset's modeling, selection, and evaluation roles separately.
- Counting field prefixes can reproduce a report while still failing to measure its prose claim. Publish the predicate and distinguish explicit positive labels from all substantively relevant comparisons.
- Do not repair a verifier solely to force a pass. In the observed review, changing equality to a prefix check was justified by inspecting the four parenthetically qualified original values.
- A review outcome of implementation passed with bounded semantic repairs pending is valid. Do not overwrite historical corrections or claim unconditional closure while those repairs remain open.

### Incremental Reacceptance

When the executor returns only the previously requested repairs, review that increment and preserve the first acceptance package. This does not authorize the reviewer to become the correction-table writer or reopen already closed findings without new evidence.

1. Use PI read and bash to compare the delivered correction ledger with the prior input snapshot. Check that the entire prior file is an exact byte prefix of the new file, then verify the appended identifiers, ordered record–field pairs, and strict sequential old values. In the observed recheck, the original 165 corrections were preserved and exactly EXC-166–174 were appended. Compare protected artifacts and the first acceptance manifest separately; matching newly reported hashes alone does not prove historical preservation.
2. Reuse an inspected independent verifier with its output redirected to a new review directory. Preserve the old verifier, report, snapshots, and manifest. The observed invocation was `python3 '<example_case_dir>/search-run/qc/ds-extraction-dispatch-20261113/implementation-recheck/validate-delta.py'`. Its results were 565 base checks and 25 increment checks passing, with no failures; seven reported hashes matched. These 590 checks measured structure and consistency, not 590 independently verified scientific facts.
3. If the executor changed the view generator, inspect the changed function and exercise it only against copies in a scratch temporary directory. Compare all three generated views against both the prior and current snapshots. Inject a deliberately incorrect old value into the copied ledger and require rejection. The observed negative control returned `EXC-166: old value does not match ex-methods.csv R00366.holdout`. Do not run the project's append script or write generated views into the project data directory merely to test them.
4. Trace selection leakage to the exact evaluation object and metric. For R01103, L663 selected SAF/LAF/NAF association-frequency distance thresholds by experimental correlation; L76 compared SAF with DNA-MERFISH, and L80 reported TSA-seq, pA-DamID, and DNA-MERFISH LAF separately. That passage did not justify declaring every DamID/TSA-seq comparison non-independent. Keep other comparisons' full-workflow independence unverified unless their own selection path has been traced; do not reverse the unsupported negative into an unsupported positive.
5. Preserve internal holdout as a distinct design. R01103 L29 described randomly removing 50% of Hi-C entries before modeling and predicting those entries. This supports a same-modality entry holdout even though it is not external data; whether full-workflow parameter selection was independent of those entries remained unaudited. Keep `holdout` and `ext_role` consistent without erasing this distinction.
6. Recompute any statistics affected by the repair and state the predicate. The observed holdout prefixes were 是91、无外部评价60、否8、未检查8, but a row beginning with 否 also described a same-modality holdout, so prefix counts were not a complete census of holdout designs. A proposed change to an 是 prefix implied 92/60/7/8 only as an expectation requiring actual recomputation.
7. Save a new report with finding-level dispositions and exact remaining record–field pairs. In the observed increment, IA-02 through IA-05 closed, while IA-01 retained only R01103 `holdout` and `ext_role`. Provide bounded replacement wording for the assigned executor to append, preserve the original corrections, and acknowledge any ambiguity in the reviewer's earlier instruction. Save current input snapshots and a separate manifest, verify its entries, and append the review trace. Proposed replacement text is not evidence that the executor has applied it.

### Binding Errata for Conflicting Verification Attachments

Use this variant when a review report claims its auxiliary JSON supports closure but the attachment retains failures. It checks whether the conclusion has other valid evidence; it does not erase failed results or authorize changes to delivered data.

1. Use PI read to inspect the report, each cited result JSON, and the corresponding verifier source. Compare individual checks rather than trusting the report's summary or the script's exit status. In the observed review, `ds-independent-checks-result.json` contained 24 passes and 3 failures although the report attributed successful reconstruction and eligibility-set checks to it.
2. Trace failed checks to their actual implementation and input schema. The observed auxiliary script skipped `record_id` corrections and omitted delayed migration, migration notes, and sorting; it also read nonexistent `verdict` instead of actual `decision`, producing `ft_included=0`. These defects explain why that attachment cannot support the claimed checks. They do not, by themselves, establish that the underlying tables are correct. Do not preserve this defective algorithm as a reconstruction recipe.
3. Inspect a separate verifier that implements the intended contract, then rerun with outputs isolated from existing artifacts. The observed invocation was `python3 <example_case_dir>/search-run/qc/ds-extraction-dispatch-20261113/implementation-final/ds-handoff/lead-review-verify.py`. Its underlying verifier performed strict old-value replay, delayed key migration, migration-note addition, sorting, byte comparisons for all three current tables, and per-stream A/B equality against final `decision` values. Attribute acceptance only to checks actually implemented and observed passing.
4. Separate historical and current results. In this review, historical 603 passes became current 602 passes with exactly one failed `marker_unchanged` check. A full row-and-column comparison found 14 changed cells, all in `是否需要研究者确认`, across 39 data rows; the file changed from 29546 to 30750 bytes. All 32 artifacts across three manifests still matched their hashes. Record the complete difference and preserve both result sets. A later mtime and confirmation text support a compatible chronology, not independent authentication of the researcher or original authorization.
5. If the substantive conclusion is supported, save a separate binding erratum using an explicit disposition such as `accepted_with_binding_errata`. Name the inaccurate report claim, retain the original failed JSON and script, identify replacement evidence, and distinguish report-level correction from data repair. In the observed case, IA-01 through IA-05 remained closed with zero batch field repairs; the erratum rejected the auxiliary JSON's claimed evidentiary role. If replacement evidence does not establish the required checks, leave those claims unresolved.

Pitfalls: a wrapper exiting 0 after catching an expected assertion does not mean every underlying check passed. In this review the wrapper explicitly verified the sole `marker_unchanged` failure; it could not be described as a current 603-pass run. Likewise, a valid closure conclusion does not make every cited attachment valid, and a script defect is not sufficient grounds to dismiss a failure without an independent check.

Verification: the saved review identifies the auxiliary attachment's three failures, cites the independently passing replacement checks, records historical 603 versus current 602 with the exact remaining failure, and states both the acceptance disposition and remaining batch repairs without overwriting original evidence.

### Isolated Reruns Against a Changing Workspace

Use this procedure when a final acceptance report claims a fixed check count but a later independent rerun observes changed project state. It verifies reproducibility at the current observation point; it does not reconstruct an earlier environment from timestamps alone or authorize changing protected inputs to obtain a pass.

1. Use PI read to inspect the final validator and every validator it loads before execution. Identify all output destinations, including destinations embedded in dynamically executed source. Redirect each destination into a fresh scratch directory or the authorized review directory, preserve the original scripts and historical JSON results, and retain the adapted runner and actual output. Run from the required project root when the validator uses `ROOT=Path.cwd()`.
2. Report the measured split rather than copying the historical total. In the observed rerun, the historical claim was 603 passing checks; the isolated result was 567 base passes, zero base failures, 35 delta passes, and one delta failure named `marker_unchanged`: 602 passes out of 603. An explained failure remains a failed assertion in the raw rerun result.
3. Investigate a preservation failure at both byte and field levels. Compare the live file with the specific snapshot used by the assertion; measure hashes, byte counts, row counts, headers, changed record identities, and changed columns. Check BOM and line endings before attributing a difference to substantive content. Here, `plan/search-pilot/marker-resolution.csv` changed from 29546 to 30750 bytes while retaining 39 data rows, the same header, and CRLF line endings; differences were confined to `是否需要研究者确认`, including `是` becoming a longer recorded researcher-confirmation statement.
4. Separate observation from attribution. The live file's recorded modification time was 22:17, later than the reported 22:09/22:10 acceptance artifacts. Together with the field diff, this supported a later confirmation-state update as the explanation for non-reproduction. Modification time and a confirmation statement inside a file do not independently prove the author, authorization, or historical execution sequence. Consult an existing decision or trace if stronger attribution is necessary; otherwise state that limit. Do not classify this as an extraction-data defect or falsified historical report without further evidence.
5. Preserve two verdicts: the extraction implementation checks that currently reproduce, and the historical preservation assertion that cannot currently reproduce. Do not restore the older confirmation column, weaken the assertion, overwrite the snapshot, or silently claim 603/603. Save the raw 567-plus-35 result and the discrepancy analysis separately.
6. Rebuild current views only in an isolated copy after inspecting `ex_tool.py`. In the observed run, delayed key migration and strict old-value checks produced 167 method rows with 87 field updates and one move, 63 review rows with 88 field updates, and four dataset rows; all three outputs matched the delivered views byte for byte. This supported implementation consistency despite the unrelated marker-file drift. It did not establish a fresh scientific audit.
7. Complete the actual review artifact before returning a completion statement. Use PI write to save the requested report with measured counts, reproduced claims, the explained discrepancy, checks not repeated, and evidence boundaries; then use PI read or bash to confirm the report exists and contains the verdict. A host `completed` state, copied auxiliary JSON, or a context summary does not establish delivery of the requested report. In this observed continuation, auxiliary results were saved but the transcript ended before the requested `DeepSeek-最终验收复核.md` was written, so report delivery remained unverified.

Verification: the preserved rerun JSON retains the actual failing assertion, and a separately saved review report states the current counts and scope without overwriting historical evidence. Do not mark review delivery complete until that report exists.

### Final Closure of a Bounded Repair

When the executor returns the last outstanding record–field repairs, use PI read and bash to verify actual application before closing the findings. This is a final incremental implementation acceptance, not a new full-text audit or authorization to rewrite extraction tables.

1. Compare the current ledger with the immediately preceding input snapshot. Require the complete prior bytes as a prefix, exactly the authorized appended identifiers and record–field pairs, and each appended `old` equal to the preceding current value. In the observed closure, 174 previous corrections were preserved and exactly `EXC-175` and `EXC-176` were appended for `R01103.holdout` and `R01103.ext_role`, both marked `IA-01b`.
2. Compare every cell of the preceding and delivered current tables, requiring the changed-cell set to equal the authorized repair set. Merely finding the two expected new values would miss unrelated changes. Independently replay the full correction chain and compare all three serialized views byte for byte; verify reported hashes, unchanged generator bytes, protected inputs, and both prior acceptance manifests. Do not run append writers to inspect their outputs. If the generator is byte-identical to the version already exercised with a bad-old negative control, retain that earlier evidence rather than claiming a new negative-control run.
3. Check the repaired semantics against the prior adjudication while preserving its unknowns. The observed repair recognized the 50% Hi-C entry holdout, limited the negative independence judgment to SAF/LAF/NAF threshold selection, and left other orthogonal comparisons' full-workflow independence unverified. This closed the requested wording repair without establishing those unknown comparisons as independent.
4. Save and run a separate final verifier. The observed command was `python3 '<example_case_dir>/search-run/qc/ds-extraction-dispatch-20261113/implementation-final/validate-final.py'`; its output reported `base_pass: 567`, `delta_pass: 36`, empty failure lists, and exactly the two intended changed cells. Attribute the resulting 603 checks to structural and consistency verification, not 603 independently verified scientific claims. Recomputed holdout prefixes were 是92、无外部评价60、否7、未检查8; these measured field wording, not an exhaustive census of holdout designs.
5. Reconcile counts by their units before writing the closure. In this delivery, 174 original Lead dispositions comprised 155 appended corrections and 19 retained values, while the final ledger had 176 correction rows: 6 original corrections + 155 work-order corrections + 4 key-migration corrections + 9 first-round repairs + 2 final repairs. Neither 176 work-order items nor 176 factual errors follows from 176 ledger rows.
6. Preserve previous reports and snapshots, and write a new final report, current input snapshot, verification output, and manifest. Verify the final manifest after artifact writes settle. Explicitly state that historical pending findings are superseded by the final acceptance record within this scope; retain unresolved scientific evidence limits and unrelated work states. Append the project trace after inspecting its existing content. The observed final manifest verified 10 artifacts and recorded `accepted_and_closed`.

Pitfalls: expected replacement prose alone does not prove application; expected changed cells do not exclude additional changes; a final implementation PASS does not erase source uncertainty; correction-row counts do not measure adjudicated items or factual errors. A prior successful generator test may be carried forward only with verified unchanged bytes and clear attribution.

Verification: the final evidence package shows an exact prior-ledger byte prefix, exactly the authorized appended corrections and changed cells, byte-identical independent reconstruction of all delivered views, verified prior and final manifests, and a scoped closure report naming the findings closed and evidence limits retained.

Additional pitfalls: a successful negative-control rejection proves the exercised generator branch, not general correctness; a leading 否 can conceal a separately described internal holdout; and selection of one association-frequency threshold cannot be generalized to every evaluation using a related modality.

### Verification

The saved report must link to verifier results showing complete disposition mapping, strict sequential old-value checks, unique final keys, and reconstructed current-view equality, while separately listing unresolved semantic repairs. For incremental reacceptance, also require exact preservation of the prior correction prefix and acceptance artifacts, exact appended scope, and isolated generator checks when its implementation changed. The first observed acceptance passed 556 structural checks with five repair groups pending; the subsequent increment passed 590 structural checks and the isolated generator tests, closed IA-02 through IA-05, and left R01103 `holdout` and `ext_role` pending. No completion of those final two repairs was established.

## Bounded Extraction-Field Repair

Use this variant to repair explicitly authorized extraction fields against local source text while preserving the rest of an existing answer template. It does not authorize completing the remaining extraction backlog, accessing additional sources, or treating a paper's software URL as tested software availability.

### When to Use

- Triggers include “仅定点返修以下已填字段”, “其余行逐字段原样保留”, and “不继续425字段”.
- Use when a reviewer identifies specific evidence errors in an already partially filled CSV and requests changed-field counts and hashes.
- Don't use for unrestricted re-extraction, online code verification when networking is excluded, or rewriting protected master tables.

### Procedure

1. Use PI read to establish the authorized record–field pairs, input whitelist, writable answer file, and stopping boundary. Preserve the original CSV bytes or a comparison snapshot before editing. In the observed task, the answer file was `<example_case_dir>/search-run/qc/ds-extraction/answers-check-methods.csv`, with header `record_id,field,verdict,correct_value,source,note`, 500 data rows, 75 filled rows, and 425 empty rows. These are case-specific baselines.
2. Read the cited passages with sufficient surrounding context, including truncation checks. Separate the method actually used from alternatives discussed in background or comparison sections. R00235 L118 supported a Poisson model; mentioning negative binomial as another common count model at L174 did not support extracting “泊松/负二项计数” as this method's assumption.
3. Correct the full scope of the original field rather than only the reviewer's example. For species and cell-line fields, inspect every cited application cohort and preserve relevant earlier cohorts when adding omitted ones. R00235 L88 listed seven human cell lines—GM12878, HMEC, HUVEC, IMR90, K562, KBM7 and NHEK—and mouse CH12-LX. A correction addressing this cohort must still be reconciled with the field's other supported datasets; an expanded list alone does not prove completeness.
4. Distinguish `未检查` from `未报告`, and distinguish upstream processing from processing implemented by the reviewed method. R00173 L82 explicitly described coverage correction, mapping raw sequence to the genome, and using a preprocessed interaction-frequency heat map. Failed keyword searches could not support a claim that preprocessing was unmentioned. Report the stated input and upstream procedures without inventing an exact normalization algorithm or claiming that the authors performed no processing anywhere.
5. Attribute modality evidence to the study it describes. R00173's only Hi-C occurrence at L16 described another Bayesian framework, while L82 called the current input genome-wide 3C-based data. Its local `REFERENCES` section contained no entries, preventing confirmation of reference 41's assay from that carrier. Retain the supported wording and record the unresolved assay boundary rather than importing the background study's modality.
6. Verify holdout identity by dataset and inference role, not by the mere presence of a validation figure or reported correlation. In the observed R00328 passage, L393 explicitly called [29, 30] “the two Hi-C datasets used for parameter inference above”; their 5 Kb correlations of r=0.65 and r=0.85 therefore did not establish held-out performance. The additional Belton et al. Hi-C [62] and Micro-C XL [63] maps were the distinct validation datasets. A field can correctly say that a holdout exists while incorrectly identifying which datasets were held out; correct the dataset identity and retain that distinction in the note. Read the continuation of truncated passages before finalizing the role attribution.

   Put evidence limits in the affected answer rows, not only in the final receipt. For both papers' `w2a` and `w2a_reason`, the repair retained the verdict but added that the paper supplied a code address and no online accessibility or runnability check was performed. A URL establishes a reported address; it does not establish that code can currently be downloaded or run.
7. Use PI bash to parse and stage each paper's authorized edits before saving. Check the actual old verdict per row rather than assuming all targets start as `一致`: the observed first attempt raised `AssertionError: ('R00235', 'species', '有误')` before writing because that row already had verdict `有误`. Keep assertions before writes, correct mistaken preconditions against the preserved input, and verify unchanged bytes after an aborted attempt. Respect a requirement to save paper by paper.
8. Compare before and after by record–field key and column, proving that changes are confined to the authorized cells and all other payloads remain identical. Check exact header, six-column alignment, row count, unique keys, ordered identifiers, filled and empty counts, verdict counts, and correction-value rules. An ordered-ID hash alone cannot establish preservation of untouched answer content. The observed final readback reported nine changed rows, 70 `一致`, five `有误`, 425 empty rows, and five nonempty correction values. Its ordered-pair hash used `json.dumps(pairs, ensure_ascii=False)` and was `497765511983ebe390e28e181ab69c6d0c3c3e15761039c6628adde97d0d139d`; preserve serialization details when comparing hashes.
9. Read the repaired rows back from disk and report the actual changed fields, counts, source boundaries, and final file hash. The observed file hash was `c2e4ae5e3fd66a53e8ed602dc901d439dfcc0d02228e16c30e2fa3b8cf1f665c`. This identifies that revision only; do not reuse it as another task's expected result. Stop without filling the remaining 425 fields.

### Pitfalls

### Pitfalls

- A valid line range and matching hash establish artifact identity, not that the cited passage supports the ruling; review the passage substantively.
- A confirmed meeting abstract does not justify inventing an earlier content exclusion from missing details; use only supported codes.
- Empty metadata relations mean no direct link was found there, not that two versions are unrelated; label any content-based judgment explicitly.
- Three-dimensional imaging, transformed point clouds, and background polymer chains do not automatically establish the protocol's required DNA trajectories or contact-to-structure inference output.
- Post-correction master hashes can legitimately differ from a frozen delivery baseline; distinguish authorized appended corrections from damage.

### Verification

The final verifier exits 0 with `status=PASS`, its identifiers equal the exact review-set union, narrative counts match derived rows, source assets match their recorded hashes, and protected masters match the delivery baseline before the assigned writer appends corrections. Scientific rulings, version-link strength, original agreement evidence and pending writeback remain explicitly distinguishable.

## When to Use

- A user asks to check paper formulas against original text, reconcile conflicting research notes, investigate a reproduction concern, or audit cross-paper benchmark comparisons.
- A study combines original manuscripts, extracted paper text, archived code, numerical experiments, and reviewer objections, and needs an independently reviewable record.
- Don't use for a simple literature summary without a verification requirement, for an ordinary code review without research claims, or as a substitute for running a requested full pipeline.

Inspect raw inputs as well as loaders before claiming that information is unavailable: the loader can discard observations that exist in the original dump. Record sample and unit definitions, masks, transforms, scales, and independent evaluation sets. For a distance RMSD over common valid unordered pairs E, the standard mean square divides by |E|; for all L points, |E|=L(L−1)/2. If a paper prints a different denominator, distinguish the printed expression from the unknown author implementation. If converting a squared quantity to a root metric, take the square root of the conversion factor and label the result conditional on the same coordinates and denominator actually being used.
6. Separate mathematical arguments from empirical checks. Do not use an observed biological example as a proof of a general identifiability theorem: in the observed audit, Bintu's three-way interactions supported cooperativity relative to expectations from pairwise frequencies, but did not directly prove that pairwise marginals cannot uniquely determine every higher-order joint distribution. Check that mathematical claim separately and distinguish an abstract probability counterexample from physically realizable chromosome configurations. For a same-library held-out split, inspect both the split and its actual use: `split_counts(C, rng, p=0.5)` generates A by binomial sampling of rounded C and B as the complementary remainder; conditional on the observed counts the halves are dependent and share library characteristics, so they are not independent biological replicates. This design limits interpretation but does not by itself quantify how much of a ranking difference it caused or guarantee its direction. For a semi-synthetic benchmark, trace measured inputs through the generator, method assumptions, calibration, and evaluation before judging model matching; generator names or broad method categories alone do not establish a bias or its magnitude. Keep potential preference as a question until the relevant comparison is performed. A positive correlation of changes measures relative ordering, not the proportion of changes with the same sign; test a sign-based outcome separately, including a rule for near-zero uncertainty. Spearman correlation is not a contribution percentage. For two estimates on shared data, compute uncertainty for their paired difference with identical resampling or deletion indices; overlap between marginal confidence intervals does not by itself determine whether that difference includes zero. In the observed K562/NONE/150 nm case, marginal intervals overlapped but the paired difference was 0.100361 with a conditional jackknife interval of [0.028173, 0.172548]. A centered jackknife interval, a bootstrap interval containing its own point estimate, or a few null intervals containing zero does not establish nominal coverage or controlled false positives. Check grouping seeds, group counts and block lengths, and validate coverage under suitable assumptions; label unvalidated intervals conditional and exploratory. When resampling repeated indices, count distinct original observations separately from resampled entries and record which strata enter each replicate. State assumptions and derive the claim, then use a small reproducible example to check an implementation. For a t-SVD tensor of shape M×M×N, the standard tubal rank is the maximum rank across frequency slices and is bounded by M; the number of independent frequencies alone does not impose a general rank bound of floor(N/2). A fully observed counterexample can refute such a universal bound but cannot establish recovery under sparse, noisy biological observations.
For repeated comparisons built from shared seeds, datasets, or overlapping genomic windows, identify the independent sampling units and preserve the rep/seed hierarchy in any joint reanalysis. Nonoverlapping windows remove locus overlap but do not establish independent biological replicates; separately resampling dependent statistics ignores their covariance and does not establish whether an interval is too narrow or too wide. Compare the implemented estimand with the planned one: a first-place disagreement is not a full-ranking or pairwise-order comparison, and a missing split-only noise baseline limits claims about exceeding all sampling noise. When the design has complete combinations, check whether a missing descriptive baseline can be computed from existing outputs: in the observed 5-seed × 5-split design, holding seed fixed and pairing splits gives 5 × C(5,2) = 50 pairwise comparisons; those pairs share observations and do not constitute 50 independent replicates. Check available records and pairing keys before proposing that calculation. Register deviations without calling a plan preregistered unless its prior freeze is independently evidenced; a rule labeled frozen in source code, or an equivalent even-window selection, does not alone establish when it was frozen.

For repeated runs, compare what the logs actually contain before interpreting replication or causality. In the observed K3 audit, six IMR90 records had the same `ValueError: model distance map must be positive and finite on every observed contact pair`; describe six occurrences of one recorded failure mode, not an independently estimated 100% failure probability. Six K562 records with different seeds had the same `(loss_last, entropy_last, argmax_entropy)` triple; this does not establish that the complete optimization trajectories were identical or that the seeds had no effect. Inspect iteration-level records and the implementation before making those stronger claims. Success in a controlled call and failure in a recommended call describe the observed input-and-call combinations; without controlled comparisons they do not uniquely identify the cause as the call path. Parse every relevant log record and distinguish a logged `status=ok` from an explicitly recorded exit code, convergence, or a checked KKT residual. In the observed audit, three COV logs contained 12 `ok` records each but no explicit return-code field; this supports 36 logged successes, not 36 independently verified exit codes or convergence certificates.

When reporting a range across simulation conditions, identify every included condition and its role, and inspect omitted conditions before treating a subset range as representative. In the observed summary, A1–A3 difference coverage ranged from 0.785 to 0.965, while A4 included 0.545 and 0.5975; the A1–A3 range remains a valid labeled subset, but a broader claim requires including A4 or a source-supported reason for exclusion. Matching an expected total row count to a factorial design supports count consistency, not provenance, uniqueness, completeness of each group, or proof that data were not concatenated; check group keys, duplicates, and records separately.

Distinguish an unconditional wrong-sign rate from the wrong-sign fraction conditional on an interval excluding zero, and specify the numerator, denominator, and simulation truth for each. In the observed C2 summary, 1 wrong exclusion among 400 repetitions was 0.0025, while 1 wrong exclusion among 35 correct plus 1 wrong exclusions was 1/36 ≈ 2.78%; neither establishes a null-effect false-positive rate. Reclassifying an interval as exploratory does not validate its coverage or support significance claims. If the required null calibration is absent, either limit the claim to conditional descriptive variation or plan a suitable calibration before making inferential claims.

7. When investigating an archived algorithm, record its archive hash, exact function, inputs, backend substitutions, and any code left unchanged. For repeated-run claims, compare logs by source, configuration, seed, error, and recorded outputs: six failures with the same `ValueError: model distance map must be positive and finite on every observed contact pair` establish six logged failures with a common error, not six independent causes or proof of determinism. Identical logged loss and entropy summaries across six seeds warrant investigation of seed propagation and saved full trajectories; selected matching summary values alone do not prove identical trajectories or lack of independence. Success under a different controlled configuration limits the scope of a recommended-path failure, but does not by itself identify its cause. Test basic invariants before an end-to-end run: a zero-threshold proximal operator should return its input; check odd and even N, real-valued inverse transforms, conjugate pairs, and phase-bearing inputs. FFT slices of real symmetric matrices can be complex symmetric without being Hermitian, so establish the Hermitian condition before using `np.linalg.svd(..., hermitian=True)`. An isolated substituted-backend failure supports a claim about that probe and snapshot, not automatically about the published pipeline or its results. Before using a suspect snapshot as a benchmark baseline, verify it in the original environment when feasible; retain the unmodified archive and any corrected version separately, identify their hashes, and compare them on the same inputs. Make the baseline identity explicit in acceptance criteria. A native-environment run and comparison with the published release remain unverified until actually performed. Check transform normalization against a reference identity: NumPy `np.fft.ifft` already divides by N, so multiplying its result by N introduces a spurious failure.
8. For a reproduction-resource audit, inventory each work and version, then capture task stage, input scale, CPU, GPU, VRAM, host memory, storage, elapsed time, software, code/data availability, and evidence location. Separate an author's actual machine or allocation from a measured peak, a minimum requirement, and an untested planning budget; retain an unspecified `memory` label without guessing host RAM or VRAM. Assign timing and hardware to the exact method, experiment, chromosome, resolution, cell count, and processing stage, not to a comparator or a different figure. Wall-clock hours, CPU-hours, GPU count, GPU-hours, biological sampling times, and simulation steps are distinct quantities. For example, `20 GPUs` and `>36 hours` are not `20 GPU·h`; `23 cores` and `18 hours` are not `18 CPU-hours`. Preserve unresolved text-versus-figure discrepancies rather than choosing a favorable number. Treat review articles as not applicable to an independent method reproduction, and do not infer a lowest GPU capacity from an A100 usage report.

Inspect the actual archived implementation and dependency declarations separately from the paper's resource claims. Read selected regular archive members without executing the code, preserve their bytes and SHA-256 along with the archive hash, and record whether datasets were mirrored and whether the archive is confirmed to be the paper's run version. In the observed Tensor-FLAMINGO snapshot, `README.md`, `requirements.txt`, and `src/Paralized_Low_rank_tensor_completion_FFTW.py` documented NumPy/SciPy, pyFFTW, and Ray; `ray.init(num_cpus=n_cores)` established CPU parallelism in that inspected module, not the GPU backend used in the paper. Absence of CUDA in one inspected module is not proof that the whole pipeline lacks a GPU path. Code inspection alone does not establish installation, execution, or performance. Update stale unknowns when a verified source becomes available, but preserve the prior source and explicitly delimit what remains unknown.

9. Design any numerical grid with recorded seeds, dimensions, missingness, tolerances, stopping rules, and a success criterion fixed before summarization. Preserve per-trial failures and nonconvergence as well as summaries. In the observed audit, 900 trials covered 90 conditions with 10 seeds per condition; 532/900 satisfied the defined joint recovery criterion and 300/300 fully observed trials passed. An empirical 10/10 success rate does not establish 95% population reliability: its Wilson 95% lower bound was 0.72247. Do not transfer an empirical frontier from a dense algebraic toy to real ultra-sparse data. Independently recount convergence and the full success predicate from raw trial CSVs, treating overlapping failure categories as overlapping rather than additive: in this audit 873/900 converged, 27 did not converge, and 368 did not satisfy the joint success criterion.
10. Keep evidence layers separate in the report: original paper statements, derived results, project proposals, toy results, and unexecuted real-data experiments. For comparisons, record each method's input, output, unit of analysis, preprocessing, resolution-selection rule, validation target, and resource constraints; distinguish per-cell reconstruction from population ensembles, embedding or clustering, and whole-nucleus outputs. Scope resource failures to the exact experiment, chromosome, resolution, and input mode: in P31, Figure 7 compares single-input and 100-cell Tensor-FLAMINGO at 500 Kbp, while the text says the 20 Kbp chromosome 2 comparison used one input cell after the 100-cell run ran out of memory; Figure 8's chromosome 19 caption separately describes both input modes. Do not turn either statement into a blanket claim that all 20 Kbp comparisons used one cell or that the methods were never compared. Check the relevant figure, caption, and surrounding text before summarizing an apparent inconsistency. Cell identity labels used to evaluate clustering are not coordinate ground truth; choosing a resolution by its best ARI also conditions the resulting comparison. Imaging used for training, calibration, matching, or tuning is not independent held-out evidence; use separate evaluation data when available, and report cross-cell-type or cross-cell-line mismatches. For selected matches, distinguish matching slots from distinct measured cells and record whether reuse across inputs was checked: P11's 16 input cells each have top-20 STORM matches, giving 320 selection slots, not necessarily 320 unique or same-cell measurements. Keep its overall median correlation 0.56 separate from the conflicting example values 0.85 in the text and 0.676 in the Figure 3 caption; cite each location and leave the example discrepancy unresolved. Do not equate generated model conformations, bulk-contact subsamples, or overlapping matched items with independent measured cells. In the ChromMovie published example, 15 Patski cells were compared with eight mES FISH probe pairs while scanning 100 frame-force values from `10−3` to `103`; this is not same-cell blind validation, and the 20 bulk contact submaps used in its separate ensemble experiment are not 20 measured cells.
11. For a corpus-wide review, inventory independent works separately from version records and PDFs; byte hashes detect identical files but cannot merge semantically related preprint and published versions. Preserve the initial inventory and label delivery-time source availability separately. Count only actual initial source paths when checking historical hashes, and report missing supplements independently of full-text availability. In the observed corpus, 39 version records represented 38 independent works, with 38 initial source hashes checked; the review structured each work using problem, input, sparsity, method, contribution, validation, limits, and relation fields. Treat a matching conference template as formatting, not evidence of acceptance, and keep online publication and issue years distinct when they differ.
12. Verify the delivery with PI `bash` and `read`: check that local links and files exist, Markdown tables and code/math fences are intact, numeric outputs are finite, per-trial counts agree with summaries, and the script SHA-256 matches the run manifest. Inspect plots for legibility. When only plot labels change, regenerate the summaries and figures from preserved data, and verify the updated manifest. For a generated presentation, reconcile source-status changes and corrected claims across the build script, outline, visible slide text, and speaker notes, retaining historical access failures as dated history rather than current status. Rebuild the presentation, then use `python-pptx` to check slide count, text in both shapes and table cells, notes, appendix coverage, embedded images, and shape bounds; identify the correct slide by its title and content rather than assuming a reviewer's page number is correct. In the observed delivery, the P15 appendix entry was on S24 (A2, P11–P20), not the review's S23 (A1, P01–P10). `soffice --headless --convert-to pdf` produced a 28-page PDF, which confirms conversion and page count but not visual legibility or absence of text overflow; inspect rendered pages separately before claiming a visual review. Syntax checks of shell examples are not evidence that network requests or server jobs ran.
13. Deliver paths, evidence-backed findings, and remaining blockers to an independent reviewer. Clearly label artifact-integrity checks as such and request academic review rather than signing off the scientific conclusions yourself.

## Pitfalls

- A report's formula and its implementation may differ. Cite the printed formula as text evidence, and explicitly leave actual implementation and input dimensions unknown until checked.
- A valid source anchor proves only that the cited file, location, and excerpt match; it does not prove that the source supports the report's interpretation. Check the surrounding passage, including which variable each threshold applies to, before declaring a contradiction or requiring a correction. In this review, 210/210 anchors matched by normalized excerpt, but that was not a semantic audit of every claim.
- Similar empirical outcomes at two parameter values do not by themselves prove mathematical non-identifiability or that a broader parameter scan was not performed. Preserve the authors' stated selection process and distinguish an arbitrary choice among similar tested values from an estimated value, a fixed default, or a proof of uniqueness. A parameter can be free in a model and still be estimated or justified empirically; those descriptions are not automatically contradictory.
- A numerically successful sample illustrates a theorem or implementation; it is not the proof and does not establish biological validity. Conversely, an iterative solver that did not converge is not proof of information-theoretic impossibility.
- A mathematical equivalence between optimization objectives or joint MAP estimates does not automatically imply equivalence of full posterior distributions.
- Wider posterior intervals can reflect measurement noise, model assumptions, or inverse ambiguity; they alone do not identify biological heterogeneity. Preserve simulated ground truth and report within-cell uncertainty separately from differences between cell-level posterior means.
- A function probe that replaces FFT or parallel execution can isolate a defect, but must not be described as an unmodified full-pipeline reproduction. Record the exact substitutions and do not infer that all published results are invalid.
- `bash -n` checks syntax only; a reachable metadata page does not establish that a data file is downloadable. Separate demonstrated results from proposed server-side probes.
- A clean artifact-integrity check is not peer review. Subsequent edits can change file hashes, so time-stamp the verification and avoid presenting an earlier hash as the final hash of a modified file.

## Verification

The audit is ready for review when the output files exist, each central claim has a traceable source or explicitly labeled derivation, experiment counts match preserved trial records, script and manifest hashes agree, and unexecuted pipeline or real-data work is explicitly listed.
